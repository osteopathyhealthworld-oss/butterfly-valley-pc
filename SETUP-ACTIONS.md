# Разовая настройка сборки

Игрок скачивает готовую игру из Releases. Godot, Git и токен для запуска не нужны.

Для сборки владелец задаёт два секрета в Settings → Secrets and variables →
Actions → New repository secret:

- **VALLEY_ASSETS_MANIFEST** — подготовленная однострочная конфигурация JSON
  закрытого хранилища ресурсов. Она задаёт источник, закреплённую версию,
  назначения, размеры и контрольные суммы. Её содержимое не публикуется в Git.
- **VALLEY_ASSETS_TOKEN** — fine-grained personal access token владельца
  хранилища: Repository access → Only select repositories → только репозиторий
  ресурсов; Repository permissions → Contents: Read-only. Metadata добавляется
  автоматически. Задайте ограниченный срок действия.

Токен создаётся в аккаунте владельца хранилища: Settings → Developer settings →
Personal access tokens → Fine-grained tokens. Сохраните его сразу как секрет
**VALLEY_ASSETS_TOKEN** в репозитории игры. Не передавайте значение в чат,
README, workflow или другие файлы Git. После истечения срока замените секрет.

Затем запустите Actions → Build Windows → Run workflow для основной ветки.
Обычный GITHUB_TOKEN этого проекта не читает другой закрытый репозиторий.
Конфигурация и токен не добавляются в игру, публичный Git или архив выпуска.

Локальная разработка допускает файл `private-assets/asset-manifest.json`
вместо первого секрета; эта папка исключена из Git. Для скачивания по-прежнему
нужно передать токен через окружение. При наличии всех проверенных ресурсов
повторное скачивание и токен не требуются.

Полученные исходные модели не коммитятся. В Releases публикуется игра:
EXE/PCK, инструкция, указания авторов и контрольные суммы архива.
При отсутствии ресурса, ошибке импорта или сбое теста выпуск останавливается.
